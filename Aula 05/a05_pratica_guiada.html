Prática guiada — parametrizando testes de desconto

Siga os passos abaixo para transformar testes repetidos em um único teste parametrizado.

1
Criar a classe Desconto
▶

Crie a classe utilitária Desconto com o método estático que aplica 10% de desconto se o valor for maior que 100, senão retorna o valor original.

public class Desconto {
    public static double aplicar(double valor) {
        if (valor > 100) {
            return valor * 0.9;
        }
        return valor;
    }
}
Métodos static pertencem à classe, não a uma instância — por isso chamamos Desconto.aplicar(...), sem usar "new".
2
Escrever o método parametrizado com @CsvSource
▶

Escreva um teste com pelo menos 4 linhas de dados, cobrindo valores acima e abaixo de 100.

@ParameterizedTest
@CsvSource({
    "50, 50",
    "100, 100",
    "200, 180",
    "1000, 900"
})
void aplicarDescontoDeveCalcularCorretamente(double valor, double esperado) {
    assertEquals(esperado, Desconto.aplicar(valor));
}
Repare que testamos o valor limite (100) — casos de "fronteira" são sempre importantes de cobrir.
3
Adicionar um teste com @ValueSource
▶

Escreva um teste que confirma que valores negativos não recebem desconto (retornam o próprio valor).

@ParameterizedTest
@ValueSource(doubles = {-10, -50, -1})
void valoresNegativosNaoDevemTerDesconto(double valor) {
    assertEquals(valor, Desconto.aplicar(valor));
}
@ValueSource(doubles = {...}) funciona igual ao de strings, mas para valores double.
4
Adicionar um @Timeout
▶

Garanta que o método Desconto.aplicar() executa em menos de 100ms.

@Test @Timeout(value = 100, unit = TimeUnit.MILLISECONDS) void aplicarDescontoDeveSerRapido() { Desconto.aplicar(150); }
Não esqueça o import: "import java.util.concurrent.TimeUnit;"
5
Executar e comparar com a versão repetida
▶

Rode a classe inteira e reflita: quantas linhas de código você economizou em comparação a escrever um @Test para cada caso?
